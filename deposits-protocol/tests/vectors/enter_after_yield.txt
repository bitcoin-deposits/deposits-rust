# DEP-06 "A yield binds only its author" (ruled 2026-11-24): the one place another member acts on
# a yield is a disputant's later DisputeEnter arriving on its yielded fork.  It is taken only on a
# valid verdict; pending counts as live, so the new entry waits (and is asked again on the next
# tip), and so does one after an invalid yield.  superseded_by is judged from the updates alone;
# lost_to, excluded_by and reestablished use the chain view.  Read through DEP-03 "The dispute"
# (dispute_scope): a disputant counts through its latest DisputeEnter at or above Q, past a
# yielded fork only on a valid verdict (then at the same sequence too).
#
# deposits-rust: deposits-core/tests/enter_after_yield_vector.rs (rotation_order::dispute_scope_with,
# reentry_yield_verdict).  cl-deposits: inspect/lottery-test.lisp (dispute-scope :chain,
# reentry-yield-verdict, and the ingest's reentry-takes-p).
#
#   u <who> <seq> <kind> [args] [h=<height>] [on=<tag>] [as=<tag>]
#       who: o = the ledger's operator, a..z = disputants.  The update's tag is <who>:<seq>, or
#       as=<tag>.  h: its signed block_height (default 0).
#       kinds: open | other | qb [tx=<name>] | enter <lvs> [punitive] [offledger] | arm [<round>]
#              | yield [lost_to=<name>] [excluded_by=<name>] [reestablished=<tag>] [superseded_by=<tag>]
#   chain <name> <height>    transaction <name> confirmed at <height>; any other is unconfirmed
#   nochain                  the judge has no chain view: a chain reason reads as published
#   verdict <tag> valid|invalid|pending    reentry_yield_verdict of that yield
#   expect <tag> ...         dispute_scope's kept updates, in input order
#   end
#
# Building the updates (both harnesses alike):
#   ledger_id = 32 x 0x09, block_hash = 32 x 0x01, operator_signature = 64 x 0, block_height = h.
#   Each who is a distinct key.  An update's content hash is the implementation's own:
#   deposits-rust sets the field to SHA256("enter_after_yield:" || tag) (it is not recomputed),
#   cl-deposits computes it from the header (DEP-02); its chain hash is SHA256(content hash ||
#   signature) either way.  REF(tag) = the content hash, and CHAIN(tag) the chain hash, of the
#   update built earlier in the case under that tag; of a tag not built (yet), SHA256 of
#   "enter_after_yield:" || tag, and SHA256 of that || 64 x 0.  txid(name) = SHA256("tx:" ||
#   name), internal byte order.
#   previous_hash: the operator's: CHAIN(its previous update) (32 x 0 at seq 0).  A
#   DisputeEnter's: CHAIN("o:<lvs>"), or 32 x 0xEE when offledger.  Any other disputant update's:
#   CHAIN(the latest update on its fork so far), the fork being on=<tag> or else its author's
#   latest DisputeEnter so far.  A punitive enter's reason is "equivocation", any other
#   "quorum_expired".  A QuorumBegin's new_outpoint_txid is txid(<name>) (32 x 0x01 without
#   tx=).  A yield's TLVs: lost_to / excluded_by = txid(<name>), reestablished / superseded_by =
#   REF(<tag>).  An arm: armed_block 0, commitment 20 x 0, target "", rearm_round <round> when > 1.
#
# 1. lost_to, the claim confirmed at or below the yield's height: valid, the new entry is taken.
case lost-to-valid-takes
u o 0 open

u a 6 enter 5
